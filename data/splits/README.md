# data/splits

Small, text-only split metadata lives here and **is** tracked by git (everything
else under `data/` is ignored).

Contents:

* `cvc_clinicdb_frame_groups.csv` — frame → sequence mapping (`case_id,group_id`),
  generated by `python scripts/make_cvc_mapping.py --config ...` from the official
  CVC-ClinicDB end-frame table (`dataset.split.sequence_end_frames`, Bernal et al.,
  2015). 612 rows, 29 sequences (`seq01` … `seq29`), frames `1..612` each exactly
  once; the script verifies every `case_id` against the image filename stems.
* `cvc_clinicdb_fold0.csv` … `cvc_clinicdb_fold4.csv` — generated by
  `python scripts/make_splits.py --config ...` (columns `case_id,group_id,split,fold`).
  Fold `k` tests the videos of fold `k`, validates on fold `k+1` and trains on the
  remaining folds, so every video is a test unit exactly once.
* `cvc_clinicdb_folds.json` — provenance written by `make_splits.py`.
* `cvc_clinicdb_norm_stats.json` — per-fold **training-set** mean/std (3 RGB channels,
  computed on the 352x352 resized `[0, 1]` frames read with tifffile), generated by
  `python scripts/compute_normalization.py --config configs/cvc_clinicdb/swinunetr_2d.yaml`.
  Used by `dataset.normalization.kind: dataset` for models trained from scratch, so
  each fold is normalized with its own training intensities (never validation/test).
  Example (fold 0): mean `[0.4107, 0.2795, 0.1876]`, std `[0.3052, 0.2117, 0.1405]`.

The generated files are committed so that a reported result can be traced to the
exact frame assignment used. Regenerate with `--force` after changing the table or
the split seed. See `docs/splits.md`.
